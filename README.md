# robotics-eval-framework

A reproducible evaluation framework for robotics ML/control that **deliberately
separates three classes of evidence** and refuses to let any result blur them.

## The evidence taxonomy (the whole point of this repo)

Every reported number must declare exactly one class:

| Class | Meaning | Example |
|-------|---------|---------|
| `REAL-PUBLIC` | Real measurements collected by others and openly released | Fault F1 on the TII UAV dataset |
| `SIMULATED` | Data generated by a documented simulator/model | HOCBF violation rate over 1M sampled states |
| `CODE-VERIFIED` | Math/software verification on our own implementation | Unit-tested invariant, saturation feasibility check |

A README result **never** blurs these. A result that claims `REAL-PUBLIC` but was
produced from simulation (or vice-versa) fails validation.

## Hard rules (enforced, not aspirational)

1. **No invented results.** Every metric is written by an experiment run, never
   by hand and never by an AI agent. See `RESULT_CONTRACT.md`.
2. **Provenance or it doesn't count.** Every result manifest must carry
   `evidence_class`, `git_sha`, `dataset_sha256`, `seed`, and `split`. CI fails
   results missing any of these (`scripts/validate_results.py`).
3. **Datasets are never committed.** Only download scripts, checksums, licenses,
   and manifests live here (`data/registry/`).
4. **Adapters hard-fail until verified.** Every dataset adapter raises
   `NotImplementedError` until a human has read the source paper and confirmed
   the label/target semantics. No auto-invented label conversions.
5. **No hardware claims without hardware.** Anything requiring the physical robot
   (ESP32/WiFi/micro-ROS latency, closed-loop vehicle improvement) is out of
   scope here and must be labelled `HARDWARE` in a separate report — this
   framework only produces `REAL-PUBLIC`, `SIMULATED`, `CODE-VERIFIED`.
6. **HPC is never auto-submitted.** SLURM templates are `sbatch`-ready but a human
   launches them (they burn real allocation).

## Layout

```
data/
  registry/            one YAML per dataset: url, license, checksum, citation, schema
  source/              downloaded raw data (gitignored — never committed)
  processed/           adapter output (gitignored)
adapters/              one stub per dataset; raises NotImplementedError until verified
schema/
  result_manifest.schema.json   the required-provenance schema
scripts/
  fetch_dataset.py     download + checksum + record provenance
  validate_results.py  fails on any result missing provenance (used by CI)
  selfcheck.py         runnable proof the schema+validator work
slurm/                 sbatch templates (launch-gated, not auto-run)
results/               committed result manifests (small JSON only)
RESULT_CONTRACT.md     the operating contract for any coding agent (OpenCode)
OPENCODE_TASKS.md      the step-by-step gated workflow to run through OpenCode
```

## How to use this with OpenCode

Read `OPENCODE_TASKS.md`. It is a gated, step-by-step plan — each step stops for
your verification (especially dataset label semantics) before proceeding. Do not
run it as "build everything." The gates are the feature.

## Quick self-check

```bash
python scripts/selfcheck.py    # proves the schema + validator reject bad results
```
